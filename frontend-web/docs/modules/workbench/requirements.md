# 分析工作台首页需求文档

## 1. 文档目的

本文档定义 `frontend-web` 首页工作台模块的 MVP 需求，用于指导前端首页设计、联调、验收与后续拆分实现。

首页不是营销门户，而是已登录分析用户进入系统后的主工作台，负责承载“选数据集 -> 提问题 -> 看任务过程 -> 看结果”的完整首屏链路。

## 2. 模块定位

模块路径建议：

- `app/page.tsx`：首页路由入口
- `features/workbench-page.tsx`：首页工作台编排
- `features/upload-panel.tsx`：数据集选择与任务提交区
- `components/task-stream.tsx`：任务事件流展示区
- `components/analysis-result.tsx`：结果、图表、SQL、审计展示区

首页职责：

1. 展示当前用户可访问的数据集入口
2. 支持发起自然语言分析任务
3. 实时展示任务执行过程
4. 展示最终 SQL、图表、结论和审计信息
5. 提供任务查询、切换、重试和 Trace 查看能力

首页不负责：

1. 权限真实性判断
2. SQL 执行
3. 直接连接 Python Agent
4. 直接访问 Kafka、Redis、MySQL
5. 复杂后台管理能力

## 3. 目标用户

### 3.1 主目标用户

`分析师`

核心诉求：

1. 快速选择已授权数据集
2. 用自然语言发起分析
3. 在一个页面内看到任务是否在执行、执行到了哪里、结果是否可信

### 3.2 次目标用户

`管理员`

核心诉求：

1. 快速确认数据集授权和接入状态
2. 查看高风险任务是否被拦截
3. 通过 Trace ID 辅助排查问题

## 4. 首页信息架构

首页采用单页工作台模式，推荐分为左右两列。

### 4.1 左侧任务与数据资产侧栏

应包含：

1. 页面标识与“新建分析”入口
2. 任务搜索框
3. 首页概览卡片
4. 最近任务列表
5. 已授权数据集快捷切换区
6. 跳转数据集管理页入口

### 4.2 右侧主工作区

应包含：

1. 当前任务状态栏
2. 数据集选择与问题提交区
3. 任务阶段进度区
4. SSE 任务事件流区
5. SQL 展示区
6. 分析结果区
7. 图表区
8. 审计与追踪信息区

## 5. 核心业务需求

### 5.1 数据集接入与选择

首页必须支持：

1. 查看当前用户已授权的数据集列表
2. 识别数据集类型：`csv`、`excel`、`mysql`
3. 多选数据集作为一次分析任务的输入
4. 展示基础元数据：
   `dataset_id`、`dataset_name`、`dataset_type`、`schema_summary`、`permission_scope`、`created_at`
5. 展示数据集摘要字段，帮助用户判断是否适合本次分析
6. 提供进入数据集管理页或打开数据集接入面板的入口

MVP 不要求：

1. 首页内完成复杂授权配置
2. 首页内完成完整数据预览表格编辑

### 5.2 自然语言任务提交

首页必须支持：

1. 输入自然语言分析问题
2. 至少选择一个数据集后才能提交
3. 允许选择图表偏好：
   `auto`、`line`、`bar`、`pie`
4. 提交任务时调用 Java 后端统一 API
5. 创建成功后立即切换到新任务详情视图
6. 展示任务创建中的加载状态
7. 阻止重复提交

前端校验至少包括：

1. 未选数据集时禁止提交
2. 问题为空时禁止提交
3. 提交中按钮禁用

### 5.3 任务过程可视化

首页必须通过 SSE 展示任务执行过程，至少覆盖以下事件：

1. `task_started`
2. `context_built`
3. `sql_generated`
4. `query_executed`
5. `chart_ready`
6. `task_finished`
7. `task_failed`
8. `human_review_required`

每个事件至少展示：

1. 事件名称
2. 事件时间
3. 事件说明
4. `trace_id`
5. 严重级别：`info`、`warning`、`success`、`error`

首页还必须展示：

1. 任务整体状态：`queued`、`running`、`needs_review`、`succeeded`、`failed`
2. SSE 连接状态：`idle`、`connecting`、`open`、`closed`、`error`
3. 当前阶段进度

### 5.4 结果展示

任务完成后首页必须展示：

1. 最终分析结论文本
2. 最终执行 SQL
3. SQL 生成理由或解释
4. 图表配置渲染结果
5. 警告信息
6. 任务耗时
7. `task_id`
8. `trace_id`
9. 关联数据集名称

图表要求：

1. 支持折线图、柱状图、饼图
2. 前端直接消费结构化图表配置渲染
3. 图表区域在无结果时展示空态说明

SQL 展示要求：

1. 明确标注“只读 SQL”
2. 支持长 SQL 展开/收起
3. 对被拦截任务展示风控状态

### 5.5 异常、空结果与审核态

首页必须显式区分以下场景，不能统一展示为“失败”：

1. `empty`
   查询成功但结果为空
2. `blocked`
   风控或越权拦截
3. `review`
   命中高风险规则，等待人工确认说明
4. `failed`
   任务执行失败

各场景展示要求：

1. 空结果：提示用户调整时间范围、筛选条件或问题表达
2. 越权/风控拦截：展示明确原因，不展示误导性的成功态
3. 人工审核态：展示审核说明和风险提示
4. 执行失败：展示失败原因与 Trace ID

### 5.6 任务历史与重试

首页必须支持：

1. 查看最近任务列表
2. 按问题文本、`task_id`、`trace_id` 搜索任务
3. 点击任务后切换当前任务详情
4. 对当前任务执行“重试”
5. 复制当前任务 `trace_id`

MVP 中“重试”含义：

1. 使用当前任务的 `question`、`dataset_ids`、`chart_preferences` 重新创建新任务
2. 不复用旧 `task_id`

## 6. 交互与状态要求

### 6.1 页面状态

首页至少需要覆盖以下 UI 状态：

1. 首次进入无任务状态
2. 数据加载中
3. 任务提交中
4. SSE 连接中
5. 任务执行中
6. 任务完成
7. 空结果
8. 审核中
9. 执行失败
10. 接口错误

### 6.2 页面响应原则

1. 提交任务后，用户应在 1 秒内看到本地任务占位与状态变化
2. SSE 事件到达后，页面应实时刷新对应区域
3. 切换历史任务时，不应影响正在执行任务的事件订阅
4. 搜索任务时应避免输入卡顿

## 7. 安全与边界要求

首页必须遵循以下边界：

1. 所有权限结果以 Java 后端返回为准
2. 前端不得自行判定是否可访问某数据集
3. 前端不得直连 `backend-agent`
4. 前端不得自行推导最终任务状态
5. 所有 SQL 展示都视为服务端最终结果回传
6. 富文本或服务端返回说明必须按安全方式渲染

## 8. 非功能需求

### 8.1 性能

1. 首页首屏应优先加载基础骨架与最近任务
2. 常规任务在演示数据规模下应在 `30 秒` 内获得最终状态
3. SSE 关键事件应尽量实时显示

### 8.2 可用性

1. 页面在桌面端和移动端均可访问
2. 核心操作按钮文案必须明确
3. 空态、失败态、审核态必须可区分

### 8.3 可维护性

1. 页面编排放在 `features/workbench-page.tsx`
2. 可复用展示块放在 `components/`
3. 前端共享契约统一维护在 `lib/types.ts` 和 API client 中

## 9. 验收标准

满足以下条件可视为首页 MVP 达标：

1. 用户进入 `/` 后可看到单页分析工作台
2. 用户可看到已授权数据集并进行多选
3. 用户可输入自然语言问题并创建任务
4. 创建任务后可实时看到 SSE 任务事件
5. 页面可展示任务状态、连接状态和阶段进度
6. 成功任务可展示结论、SQL、图表和审计信息
7. 空结果、审核态、失败态和风控拦截态均有独立展示
8. 用户可搜索历史任务、切换查看、复制 Trace ID、重试任务

## 10. 实施建议

建议将首页拆成以下前端子模块实现：

1. `workbench-page`：页面状态编排与任务上下文切换
2. `upload-panel`：数据集选择、问题输入、提交动作
3. `task-stream`：SSE 连接状态与事件时间线
4. `analysis-result`：结论、SQL、图表、审计信息
5. `status-badge`：状态标签统一视觉规范

这样可以保证首页先打通主链路，后续再独立补强数据集管理、历史页和审核页。
